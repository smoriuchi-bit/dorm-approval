# 寮の申請・承認システム（GitHub Pages ＋ Google Apps Script 版）

創志学園高校の寮生の外泊・外出・帰省などの申請を受け付けます。承認者全員にメールで依頼し、全員の承認がそろうと許可書（PDF）を発行して、保護者にも知らせます。

- **画面**（HTML）は GitHub Pages で公開します。
- **データの保存**は Google スプレッドシート、**メールの送信**は Gmail、**処理**は Google Apps Script が担当します。
- 学校のサーバーは不要で、費用もかかりません（Google Workspace のアカウントが1つ必要です）。

```
寮生・職員のブラウザ ──▶ GitHub Pages（画面：docs フォルダ）
                              │  ログイン・申請・承認
                              ▼
                      Google Apps Script（apps-script/Code.gs）
                         ├─ Google スプレッドシート（データ）
                         └─ Gmail（通知メール）
```

## フォルダの中身

| 場所 | 内容 |
|---|---|
| `docs/` | GitHub Pages で公開する画面（index.html・approve.html・config.js・assets） |
| `apps-script/Code.gs` | Apps Script に貼り付けるプログラム |

---

## 設置手順

### 手順1　送信用の Google アカウントを決める

通知メールは、Apps Script を公開した Google アカウントから送られます。個人のアカウントではなく、寮用の共有アカウント（例：`dorm@soshigakuen.ed.jp`）を使うことをおすすめします。以下の作業はすべてそのアカウントで行ってください。

### 手順2　スプレッドシートと Apps Script を用意する

1. Google ドライブで新しいスプレッドシートを作ります（名前の例：`寮の申請・承認データ`）。
2. メニューの **拡張機能 → Apps Script** を開きます。
3. 最初から入っている `function myFunction() {...}` をすべて消し、`apps-script/Code.gs` の中身を貼り付けて保存します。
4. 画面上部の関数の選択欄で **`setup`** を選び、**実行** を押します。
   - 「承認が必要です」と出たら、アカウントを選び、「詳細 → （安全ではないページ）に移動 → 許可」と進みます。自分で作ったスクリプトなので問題ありません。
   - スプレッドシートに `users` `requests` などのシートができれば成功です。

> スプレッドシートには寮生や保護者の個人情報が入ります。**共有しないでください。**

### 手順3　ウェブアプリとして公開する

1. Apps Script の右上 **デプロイ → 新しいデプロイ** を押します。
2. 歯車アイコンから **ウェブアプリ** を選びます。
3. 次のように設定して **デプロイ** を押します。
   - 説明：`寮の申請・承認`
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
4. 表示された **ウェブアプリの URL**（`https://script.google.com/macros/s/……/exec`）をコピーします。

> 「全員」が選べない場合は、Google Workspace の管理者が外部公開を制限しています。管理コンソールで、Apps Script のウェブアプリを「全員」に公開できるよう許可してもらってください。
> 「全員」にしても、ログインしていない人はデータを見たり操作したりできません（このシステム自体がログインで確認します）。

### 手順4　GitHub Pages で画面を公開する

1. GitHub で新しいリポジトリを作ります（例：`dorm-approval`）。
2. このフォルダの中身（`docs` フォルダ・`apps-script` フォルダ・`README.md`）をアップロードします。
3. `docs/config.js` を開き、`XXXX` の行を手順3でコピーしたURLに書き換えて保存します。
   ```js
   window.DORM_API = 'https://script.google.com/macros/s/AKfycb……/exec';
   ```
4. リポジトリの **Settings → Pages** で次のように設定します。
   - Source：**Deploy from a branch**
   - Branch：**main**、フォルダ：**/docs** → Save
5. 1〜2分で `https://（GitHubのユーザー名）.github.io/dorm-approval/` が公開されます。

> リポジトリは公開（Public）で問題ありません。GitHub に置くのは画面のプログラムだけで、個人情報やパスワードは入っていません。データはすべてスプレッドシートに保存されます。

### 手順5　初期設定

1. 公開されたページを開くと「初期設定」画面が出ます。学校名・管理者（あなた）の氏名・メールアドレス・パスワードを登録します。
   - このとき、画面のURLも自動で登録されます。メールのボタンのリンク先になります。
2. **設定 → 基本設定 → 自分にテストメールを送る** で、メールが届くことを確認します。

## 使い始めるまでの流れ（管理者）

1. **名簿**（設定 → 名簿）に、職員・保護者・寮生の順で登録します。
   - 寮生には「担任」と「保護者」を設定します。担任は承認者画面の「担任クラスの申請」で、クラスの寮生の申請を一覧で確認でき、CSVでも保存できます。
   - 「保存したあと、パスワードを決めるための案内メールを送る」にチェックすると、本人にメールが届きます。本人がパスワードを決めると使い始められます。
   - 保護者はログインしなくても、承認完了のお知らせメールを受け取れます。
2. **承認ルート**（設定 → 承認ルート）を作ります。ルートに入れた職員全員に同時に承認依頼が届き、全員が承認すると許可になります。
3. **申請の種類**（設定 → 申請の種類）を作ります。「外泊・外出・帰省のひな形を入れる」で3種類をまとめて登録できます。入力項目は自由に追加・並べ替えできます。

## 承認の流れ

1. 寮生が申請すると、承認ルートの職員全員に「承認依頼」メール、寮生に「受付」メールが届きます。
2. 承認者は、メールの **「承認する」「承認しない」** ボタンから回答します（ログイン不要）。承認者画面から回答することもできます。
   - ボタンを押すと確認ページが開き、「回答を確定する」を押したときに記録されます。メールのセキュリティ機能がリンクを自動で開いても、誤って承認されることはありません。
   - リンクは一度使うと無効になります。
3. 全員が承認すると、寮生に「許可」、保護者に「お知らせ」、承認者全員に「承認完了」のメールが届きます。許可書は申請一覧からPDFで保存できます。
4. 1人でも「承認しない」を選ぶと、寮生と承認者に「非承認」のメールが届きます。

## 画面と権限

| 利用者 | 使える画面 |
|---|---|
| 寮生 | 申請する、申請一覧（自分の申請のみ） |
| 保護者 | 申請一覧（子どもの申請のみ） |
| 職員 | 承認者画面（承認待ち／進行中／判断済み／担任クラスの申請）、代理申請、申請一覧（全員分） |
| 管理者（職員） | 上の画面に加えて、送信メール、設定 |

## スマホで使う（ホーム画面に追加）

このシステムはスマホのアプリのように使えます（App Store などからのインストールは不要です）。

- **iPhone**：Safari で画面を開き、下の共有ボタン（□に↑）→「ホーム画面に追加」→「追加」。
- **Android**：Chrome で画面を開くと「ホーム画面に追加」の案内が出ます。出ないときは右上の「︙」→「ホーム画面に追加」（または「アプリをインストール」）。

ホーム画面の「寮の申請」アイコンから開くと、ブラウザの枠のない全画面で表示され、下のタブで画面を切り替えられます。

> iPhone では、ホーム画面から開いたアプリと Safari とでログインが別々になります。メールのボタンから開いた承認ページはログイン不要なので、そのまま回答できます。

## 運用のメモ

### プログラムを直したとき

- **画面（docs）を直したとき**：GitHub に上げ直すだけで、数分で反映されます。
- **画面を直したとき（docs）**：`docs/sw.js` の先頭にある `VERSION` の数字も変えてください。スマホに保存された古い画面が新しいものに入れ替わります。
- **Code.gs を直したとき**：Apps Script に貼り付けて保存したあと、**デプロイ → デプロイを管理 → 鉛筆アイコン → バージョン：新バージョン → デプロイ** を行います。こうするとURLが変わらず、config.js を書き換える必要はありません（「新しいデプロイ」を選ぶとURLが変わるので注意）。

### メールの上限

Google Workspace のアカウントでは、1日に約1,500人まで送れます（無料の Gmail アカウントは約100人）。残りの数は「設定 → 基本設定」と「送信メール」で確認できます。送れなかったメールは「送信メール」に残り、「送り直す」で再送できます。

### 表示の速さとキャッシュ

画面を速く表示するため、Apps Script はスプレッドシートの内容を一時的に保存（キャッシュ）して使います。画面から行った操作はすぐに反映されます。

スプレッドシートを**直接**書き換えたときは、管理者が「設定 → 基本設定 → スプレッドシートから読み直す」を押してください（押さなくても6時間以内に読み直されます）。

1年より前に終わった申請は、画面を軽く保つため最初は表示しません。申請一覧の「表示する」で見られます。

### データのバックアップ

データはスプレッドシートにあります。**ファイル → コピーを作成** や、ドライブの版の履歴で戻すことができます。スプレッドシートを直接書き換えると不整合が起きることがあるため、修正は画面から行ってください。

### GitHub Pages のURLを変えたとき

独自ドメインにしたときなどは、**設定 → 基本設定**の「この画面のURL」を新しいURLにして保存してください。メールのボタンのリンク先が変わります。

## セキュリティについて

- パスワードは、そのまま保存せず、変換（ハッシュ化）した形でスプレッドシートに保存します。
- ログインの鍵や承認用リンクの鍵も、変換した形でだけ保存します。スプレッドシートを見ても使えません。
- 10回続けてログインに失敗すると、そのアドレスは15分間ログインできなくなります。
- ログインは30日間保たれます。共用のパソコンでは、使い終わったらログアウトしてください。

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 「config.js にApps ScriptのURLが書かれていません」 | 手順4の3を行ったか |
| 「サーバーから正しい返事がありませんでした」 | 手順3で「アクセスできるユーザー：全員」になっているか。URLが `/exec` で終わっているか |
| 「シート○○がありません」 | 手順2の4（setup の実行）を行ったか |
| メールが届かない | 「送信メール」のエラー内容。迷惑メールフォルダ。1日の上限 |
| メールのボタンを押すと違うページが開く | 「設定 → 基本設定」の「この画面のURL」 |
